# core/maps

Context maps: a user's home for working on one feature or project. Each map is a folder `.manta/maps/<id>/` in the docs repo (kept out of git like thread records, and shared later along with `.manta/`) holding `map.json` (title, description, ticket key, stage, code projects by name, launch mode, sweep and proposal settings, whether agents may accept tickets, docs with their milestones, sections and roles) and `tracker.json` (milestones with their definition of done, numbered tickets, numbered decisions). This machine's part is in `.git/manta/maps/<id>/`: launches, batches, suggestions waiting for review, Ask the map's conversation and the user's visits. `../workspaceMaps.ts` and `../mapLaunches.ts` run them; full design: [docs/context-maps.md](../../../docs/context-maps.md).

| Entry | What it does |
|---|---|
| `mapModel.ts` | The data model and its rules, pure: the stored shapes (`MapFile`, `Tracker`) and their guards, ids, milestone status (`milestoneStatus`), the current milestone, scopes (`scopeTicketIds`, `scopeTitle`), dependencies and decisions (`waitingOn`, `openDecisions`, `readyTickets`; cycles refused), ticket and decision numbers (given out by `parseTracker` and the edits, never reused), the map's key and stage (`mapKey`, `mapStage`), hand edits to the tracker (decisions included), docs and settings (`applyTrackerEdit`, `applyDocsEdit`, `applySettings`), proposed plans and plan changes (`addProposedMilestones`, which resolves dependencies by title, `applyPlanChange`, `parsePlanChange`), a pull request's health (`pullRequestHealth`), status changes from events (`setTicketStatuses`), and doc paths (`cleanDocPath`). |
| `mapActivity.ts` | The map's activity log: events from comparing the tracker (`trackerEvents`), a launch (`launchEvents`) or suggestions (`suggestionEvent`) before and after a write, the one-time backfill from what the map already dates (`backfillEvents`), and the stored event's guard (`parseMapEvent`). Pure but for ids. |
| `mapStore.ts` | `MapStore`: reads and writes the map's files (`map.json`, `tracker.json`, the append-only activity log `activity.jsonl`, append-only journals, moved there from the local state by `moveLocalJournals`) and its machine-local state (launches, batches, suggestions, Ask the map's session and conversation, visits). Writes are atomic and skip unchanged files; callers run them on the serial queue. |
| `mapBrief.ts` | What agents are told: `launchBrief` (a launched session's scoped brief: acceptance criteria, dependencies, the user's note for this start, others in the worktree, earlier wrap-ups, `workingUnderAMap`, which asks the user before proposing unless the map queues, and `finishingSteps`, with the project's checks), `MINIMAL_DOC_CHANGES`, `askSystemPrompt` and `breakDownPrompt` (Ask the map), `sweepSystemPrompt`, `sweepPrompt` and `landingPrompt` (the sweep and the landing pass), `mapOutline`, `coordinatorBrief` (a batch's coordinator), and for the brief page `ticketBriefDocs` (the docs a ticket's brief points to) and `briefReadiness`. `LAUNCH_TRAILER`. Pure. |
| `mapTools.ts` | The map tools' names, descriptions and schemas, and which callers (a session, the sweep, Ask the map, a coordinator) get each. Handlers live in `../mapLaunches.ts`. |
| `mapArgs.ts` | Validators for the map IPC arguments, which main treats as untrusted. |
| `mapMigration.ts` | Converts a v1 map (`map.md` with its Docs list) to v2. Pure. |

**Imports:** `../../shared/ipc.ts`; `mapModel.ts` uses `../threads/threadRecords.ts` (`MANTA_DIR`) and `../threads/threads.ts` (`parseMapAuthor`), `mapStore.ts` uses `../threads/threads.ts` (`isMessage`), `mapBrief.ts` uses `../threads/implementationBrief.ts` (`fenced`), `mapTools.ts` uses `../terminal/mcpEndpoint.ts` (type).

**Tests:** `__tests__/mapModel.test.ts`, `__tests__/mapActivity.test.ts`, `__tests__/mapBrief.test.ts`, `__tests__/mapArgs.test.ts`, `__tests__/mapMigration.test.ts`. The store, Ask the map and suggestions are covered end to end in `../__tests__/workspaceMaps.test.ts`; launches, tools and the sweep in `../__tests__/mapLaunches.test.ts`.
