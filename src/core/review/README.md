# core/review

Review comments: notes on diff lines (the Changes tab's and the Branch tab's diffs) that the user sends to a Claude session, one at a time or as a batch; they stay in Manta and never go to GitHub. Also the PR tab's side: a pull request's comments sent to an agent behind the user's prompt template, and creating a draft PR. Full design: [docs/reviews.md](../../../docs/reviews.md).

| Entry | What it does |
|---|---|
| `reviewComments.ts` | `ReviewCommentStore`: one worktree's comments in a JSON file (`{ "comments": [...], "prSent": {...}, "viewed": {...} }`; a PR review's pending comments are comments with `diff: 'pr:<n>'`, and `viewed` holds each PR's viewed files), added, edited, removed and marked sent on the store's own queue, written atomically; `prSent` records which pull request comments (by GitHub node id) went to which agent. `parseComment` guards each entry; unreadable ones are skipped and an unreadable file reads as empty. |
| `sendReview.ts` | `deliverPrompt`: pastes a message into a running Claude session (`TerminalManager.sendPrompt`, which refuses one that isn't ready) or starts a new session with it. `sendPullRequestComments`: a PR's chosen comments behind the user's template, marked sent in `prSent`. `sendReview`: formats the chosen stored comments as one message and sends it to a running Claude session (`TerminalManager.sendPrompt`, which refuses one that isn't ready) or starts a new session with it as the first prompt, then marks them sent to that session's title. |
| `pullRequestReview.ts` | Reviewing a pull request in Manta. `fetchPullRequestDiff` fetches its head into `refs/manta/pr/<n>` and diffs it from the merge-base with `origin/<base>`; `hunkRanges` reads which lines GitHub takes comments on; `staleComments` finds pending comments the PR moved under. `PullRequestReviews`: `open` (files with viewed ticks that hold while the file's blobs are unchanged, unpushed local commits, own PR), `postSingle` (one comment to GitHub at once), `submit` (the pending `pr:<n>` comments and the verdict in one request, cleared only when GitHub took it). |
| `pullRequestRequests.ts` | The REST bodies for a single comment and a review (`singleCommentRequest`, `reviewRequest`), and `reviewProblem`: why GitHub would refuse a review (an own-PR verdict, changes requested with no summary, an empty comment review). Pure. |
| `pullRequests.ts` | `PullRequests`: the PR tab's side of GitHub per worktree. `status` says why the tab can't work (no `gh`, no GitHub remote, not on a branch, `gh`'s own error) or gives the branch's PR or none; `createDraft` pushes what GitHub lacks then runs `gh pr create --draft`, and the next `status` skips the cache; `sendComments` sends the cached PR's chosen comments. `hasGitHubRemote`, `prBaseName`. |
| `reviewSettings.ts` | `ReviewSettings`: the user's prompt template for PR comments, in `<userData>/review-settings.json`, global; reads as `DEFAULT_PR_TEMPLATE`, unconfirmed, until the user saves one. |
| `pullRequestMessage.ts` | `formatPullRequestMessage`: the template, a line naming the PR, then each comment numbered with its author, its `file:line` and fenced hunk for review threads, its replies and its URL. Pure. |
| `reviewMessage.ts` | `formatReviewMessage`: the prompt an agent gets, a header naming the worktree then each comment numbered with its `file:line`, its diff hunk in a fenced block and its text. Pure. |

**Imports:** `../../shared/ipc.ts`; `reviewMessage.ts` and `pullRequestMessage.ts` use `../threads/implementationBrief.ts` (`fenced`); `sendReview.ts` uses `../terminal/terminals.ts` (types); `pullRequests.ts` uses `../repo/git.ts` and `../repo/github.ts`. `../workspace.ts` holds one store per worktree (`workspace.review`, `<git-dir>/manta/review-comments.json`); `main/` exposes it over IPC.

**Tests:** `__tests__/reviewComments.test.ts` (temp dirs), `__tests__/reviewMessage.test.ts`, `__tests__/pullRequestMessage.test.ts`, `__tests__/reviewSettings.test.ts` (temp dirs), `__tests__/pullRequests.test.ts` and `__tests__/pullRequestReview.test.ts` (clones of a bare temp origin standing in for GitHub, `gh` stubbed), `__tests__/pullRequestRequests.test.ts`, `__tests__/sendReview.test.ts` (a real `TerminalManager` running `scripts/fake-claude.mjs`).
