# core/repo

Git and the set of repos Manta knows about.

| Entry | What it does |
|---|---|
| `cachedRead.ts` | `CachedRead`: a value loaded on demand and kept until invalidated; readers during a load share it, a read after a mid-load invalidation gets a fresh load, and a stale read waits out a minimum gap unless the invalidation was urgent. |
| `git.ts` | `Git`: shells out to `git`; paths passed as `hidden` (the workspace passes `.manta`) are left out of status, stats and commit-all, and `excludeLocally` writes `info/exclude`; (so hooks, credentials and worktrees behave as in the terminal) for status (staged and unstaged), diffs, grep, the file list (which includes gitignored `.env*` files, but grep skips them), stage / unstage / discard, commit, fetch and fast-forward, worktrees, a branch's base (the default, or a chosen ref) and the list of branches, for creating pull requests: remote URLs, pushing a branch (`-u` the first time; never waits on a prompt, gives up after 90 s), commits ahead of the upstream and the last commit's subject; and for reviewing them: fetching refspecs, merge-base, each changed file's old and new blob (`diffBlobs`, a fingerprint of its diff) and one file's hunks. `isSafeRef` checks refs from outside before they reach git. Output parsers (`parseStatus`, `parseBranchHeader`, `parseNumstatZ`, `parseGrep`, `parseWorktrees`) are exported for tests. |
| `github.ts` | Everything Manta asks GitHub, through the user's own `gh`. `ghRunner`: runs `gh` with prompts off, a timeout and optional stdin, returning stdout or `gh`'s own error (the one seam tests stand in for). `ghPullRequests`: a branch's newest pull request for implementation chips (read-only, cached for a minute); null when `gh` is missing or fails, so a failure never reads as "no pull request". `ghPullRequestDetail`: the PR tab's view of a branch's pull request (checks, conversation, reviews, review threads) from `gh pr list`, `gh pr view` and one GraphQL query, cached a minute unless forced. `VIEWED_QUERY`, `MARK_VIEWED`, `UNMARK_VIEWED` and `parseViewedFiles`: a PR's files as viewed on github.com, and ticking them there. `parsePullRequests` and `parsePullRequestDetail` for tests; fixtures in `__tests__/fixtures/`. |
| `landing.ts` | `branchLanded`: whether work has landed on the project's default branch (local or `origin`'s), by a commit trailer or by the branch's tip being there after moving past its base. Used by implementation threads and map launches. |
| `watchIgnore.ts` | `isWatchIgnored`: whether a changed path is inside `.git`, `node_modules` or a build folder, so the file watcher doesn't refresh the panels for it. |
| `repoCache.ts` | `RepoCache` (`workspace.cache`): one repo's git status (`Git.statusSnapshot`, at most every 3 s) and file list as the panels show them; `noteEvents` classifies a batch of file events into structure, content and thread records and marks the matching caches stale. Untracked files' line counts are kept while their size and mtime stay the same. |
| `projects.ts` | `worktreeSlug` (a worktree's folder and `manta/<slug>` branch name) and `ProjectRegistry`: the docs repo plus code repos, persisted in `<userData>/settings.json`; creates and removes Manta-managed worktrees; opens one `Workspace` per root and decides which roots the renderer may touch. |

**Imports:** `git.ts` uses `../../shared/ipc.ts` and `watchIgnore.ts`; `github.ts` uses only `../../shared/ipc.ts`; `watchIgnore.ts` and `cachedRead.ts` import nothing; `repoCache.ts` uses `cachedRead.ts`, `git.ts` and `../../shared/ipc.ts`; `landing.ts` uses `git.ts`. `projects.ts` uses `git.ts`, `../workspace.ts` and `../agent/threadAgent.ts`.

**Tests:** `__tests__/git.test.ts`, `__tests__/projects.test.ts`, both against real temp repos; `__tests__/github.test.ts` against a stand-in `gh`; `__tests__/watchIgnore.test.ts`, `__tests__/cachedRead.test.ts` (fake timers) and `__tests__/repoCache.test.ts` (real temp repos).
