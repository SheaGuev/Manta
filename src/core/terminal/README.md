# core/terminal

Terminals in a context root (the docs repo or a worktree): the user's shell, or a Claude Code session whose state Manta tracks through hooks. `main/` composes these; nothing else in core uses them.

| Entry | What it does |
|---|---|
| `terminals.ts` | `TerminalManager`, what `main/` uses: creates shells and Claude sessions in a root (Claude with `--settings <hooks file> --session-id <uuid>`, or `--resume` once it has had a prompt), restarts exited ones, renames them (`rename`, kept in the record), keeps records in step, and lists terminals from before a relaunch as exited so their tabs can resume. A Claude session can also start with a first prompt (placed before every option), a brief (`--append-system-prompt-file`, refreshed before each start), extra folders (`--add-dir`), a link to the doc section it implements or to the context map it was started from, or an existing session to resume. Sessions that `mcpTools` gives tools to (implementation sessions, map launches) also get `--mcp-config` for Manta's MCP endpoint and those tools allowed (`--allowedTools`); `agentMcp` hands the same endpoint to agents Manta runs itself. `sendPrompt` types a prompt into a Claude session (bracketed paste, then Enter), refused unless it's at its prompt or working. A map session's `UserPromptSubmit` hook is answered with `promptContext`'s note as `additionalContext`. |
| `hookServer.ts` | `HookServer`: loopback HTTP endpoint with a per-run token that Claude Code's hooks post to, and that linked sessions reach Manta's MCP tools on (`/mcp/<terminal id>`, Bearer token), as do agents Manta runs itself (`/mcp/agent_<…>`). `HOOK_COMMAND` (the `curl` every hook runs, which prints Manta's answer, `{}` unless an optional `HookAnswer` adds context to a prompt, and never fails) and `claudeHookSettings()`, the `--settings` file. |
| `mcpEndpoint.ts` | `answerMcp`: Manta's MCP server for linked Claude sessions, as JSON-RPC over Streamable HTTP with JSON responses (`initialize`, `ping`, `tools/list`, `tools/call`). Generic: the tools come from the caller (`McpTool`), chosen per caller (`McpSession`: a terminal's record, or an agent id). |
| `terminalHost.ts` | `TerminalHost`: one PTY per terminal (`node-pty`) plus a headless copy of its screen (`@xterm/headless` + serialize), so a tab that mounts later gets a `snapshot` and then only newer output (`seq`). Batches output (16 ms), resizes, kills the process group (SIGHUP, then SIGKILL), applies hook events to Claude terminals. `pasteReady`: whether the program turned bracketed paste on. |
| `terminalState.ts` | `stateAfterHook`: a Claude terminal's next state (`idle` / `working` / `waiting`) from one Claude Code hook payload. Pure. |
| `terminalEnv.ts` | The environment terminals get: the user's login shell env (`loginShellEnv`), minus variables a parent Claude Code, Orca or Superset session sets for its children (`withoutSessionScoped`), plus `TERM` and Manta's ids (`terminalEnv`). |
| `claudeArgs.ts` | The user's extra `claude` arguments: `splitArgs` (shell-style words), `parseClaudeArgs` (refuses the flags Manta sets itself), `permissionSummary` (what sessions may do without asking, from the permission flags, for the brief page), and `ClaudeArgsStore`, kept in `<userData>/terminal-settings.json`. |
| `terminalRecords.ts` | `TerminalRecordStore`: open terminals in `<userData>/terminals.json`, so tabs, Claude session ids, doc and map links and briefs survive a relaunch. |

**Imports:** `../../shared/ipc.ts` only; no Electron, so it runs under vitest. `node-pty` ships N-API prebuilds that load in both Node and Electron; its `spawn-helper` needs the exec bit the `postinstall` script sets.

**Tests:** `__tests__/terminals.test.ts` runs shells and `scripts/fake-claude.mjs` (a scripted `claude` that runs the real hook command) end to end: states, resume, relaunch, closing a root, sending a prompt. `__tests__/hookServer.test.ts` posts through the real hook command with `curl`. `__tests__/terminalHost.test.ts` drives real PTYs through `/bin/sh` (batching, snapshot plus later output, resize, process-group kill, hook state). `__tests__/terminalState.test.ts` replays hook sequences in the order Claude Code sends them. `__tests__/terminalEnv.test.ts`, `__tests__/terminalRecords.test.ts`, `__tests__/claudeArgs.test.ts`, `__tests__/mcpEndpoint.test.ts`; the MCP route is in `__tests__/hookServer.test.ts`.
