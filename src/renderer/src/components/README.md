# renderer/src/components

React components. Each talks to main through `window.manta` directly or through hooks in `../lib/hooks.ts`. Logic worth testing goes in `../lib/`, not here.

| Entry | What it does |
|---|---|
| `DraftPullRequestDialog.tsx` | Create draft PR: title (the last commit's subject), base (the Branch tab's choice, else the default branch) and description; pushes first if GitHub lacks any of the branch, and shows git's or `gh`'s error in place. |
| `FinishReviewDialog.tsx` | Finish review: a summary and Comment, Approve or Request changes (only Comment on your own PR); GitHub's or Manta's refusal shows in place. |
| `ImplementDialog.tsx` | Starts an implementation thread: title, code project, new or existing worktree, first prompt; calls `startImplementation`. When a context map lists the doc, it defaults to tracking the work as a ticket of the map's current milestone (linked to the section) and launching it from the map instead. |
| `PromptTemplateDialog.tsx` | The prompt put in front of PR comments sent to an agent: asked once before the first send (filled with the default), and editable from the picker's Edit prompt…. |
| `PullRequestComments.tsx` | `usePullRequestComments`: the comment gutter for a PR review's diff. **Add single comment** posts at once, **Start a review** / **Add review comment** keeps it pending (`pr:<n>` review comments), the send icon gives it to an agent unsaved; a + only on lines inside the diff's hunks; GitHub's threads read-only under their lines. |
| `PullRequestPanel.tsx` | The right panel's PR tab: the branch's pull request (state, base, Open on GitHub, refresh), its checks (collapsed when all passed) and its comments with checkboxes, unresolved threads first and ticked; **Send N to agent…** goes through `AgentPicker` and the template. Says why when it can't work; offers Create draft PR when there's no PR. |
| `PullRequestReview.tsx` | The PR review tab: changed files with viewed ticks and an "N of M viewed" count (ticking moves to the next unviewed file), a note when the worktree has unpushed commits, **Finish review** with the pending count, and the selected file's diff. Reopens when the PR's head moves. |
| `Sidebar.tsx` | Left pane, a list of contexts in three sections, each with an action that shows on hover: **Workspace** (the docs repo; its swap button changes the docs repo), **Context maps** (a diamond when Ask the map is answering or something waits on you; the current milestone's progress on hover), and **Repositories** (code projects with their worktrees: create, remove, new Claude session). A dot on each context's row for its most urgent Claude session. Files are in the right panel. |
| `RightPanel.tsx` | Right pane with Files / Changes / Branch / PR (code repos only) / Threads tabs, file search, new file and folder, and Delete (to the Trash, closing its tabs) on a right-clicked file or folder. The tabs drop to icons only when their labels would clip. In a context map, Files and search show only the map's docs, with **Show all files**. |
| `ChangesPanel.tsx` | The Changes tab: commit message and Commit, then Staged changes and Changes with stage, unstage, discard and open per file and per section. Exports `ChangeSection` and `ChangeRow`, which the Branch tab reuses. |
| `BranchPanel.tsx` | The Branch tab: the branch it compares with (`BranchPicker`, and a note when a chosen branch is gone), Committed on branch (files changed since the branch's base) and, at the bottom, Commits, each expanding to its files. Rows open read-only diffs. |
| `BranchPicker.tsx` | "vs <branch> ▾" at the top of the Branch tab: a popover listing local and remote branches, most recent first, filtered by a fuzzy match, with **Default** first. |
| `DiffComments.tsx` | `useDiffComments`: review comments for one diff view (the comment gutter extension, the comments for its file, and the agent picker when a comment is sent straight away), as a `DiffCommentsHandle`. Used by `BranchCompareView` and the editor's diff mode. |
| `ReviewComments.tsx` | The **Comments** section at the top of the Changes and Branch tabs: that diff's review comments, unsent ones ticked, **Send N to agent…** (one message through `AgentPicker`) and **Clear sent**; a row opens its diff. Nothing when there are none. |
| `AgentPicker.tsx` | The popover that picks which Claude session gets review comments: every open one, the worktree's own first, waiting and starting ones disabled, and a new session; an optional footer (the PR tab's Edit prompt…). |
| `CompareView.tsx` | A read-only diff of one file between two commits (`unifiedMergeView` plus the overview strip), with whatever comment gutter its owner passes. `BranchCompareView`: the Branch tab's compare tabs, the whole-branch diff taking Manta's own comments. |
| `FileTree.tsx` | Recursive file tree used by the right panel. |
| `SearchResults.tsx` | File-name and content search results, grouped by file, with the query highlighted. |
| `PluginsView.tsx` | The Plugins tab (from the + menu): Mason's packages by core set, installed, languages, linters and formatters; install, update, remove, servers on and off, a custom server for a package without a recipe, live install progress. |
| `ThemePicker.tsx` | The Plugins view's Themes: Open VSX colour themes for the code editor, each variant, and back to Manta's own. |
| `QuickFixPicker.tsx` | Cmd+.: the language server's quick fixes and refactors for the cursor's line. |
| `SymbolPicker.tsx` | Cmd+Shift+O: the code file's symbols from its language server, by a fuzzy match on the name. |
| `QuickOpen.tsx` | Cmd+P: open a file in the context by a fuzzy match on its path (`name:42` opens at a line); recent files before anything is typed. |
| `ThreadList.tsx` | The open doc's threads grouped Implementations / Open / Merged / Discarded / Detached; a new thread anchors to the section at the cursor; **Implement this section…** opens the Implement dialog. |
| `ThreadView.tsx` | A thread tab: transcript (markdown, streamed), composer, permission cards, proposed-edit diff, approve / discard, subthreads. Exports `appendText` and `LINK_SAFETY`, which the map screens reuse. |
| `MapView.tsx` | A context map's tab: loads the map (`useMapDetail`), records the visit, and shows its navigation bar (Overview, Milestones, Docs, Decisions, Activity, Ask the map, and a ⋯ menu: edit, break down, pin the current milestone, remove) over the page it's on (`MapScreen`, a ticket included), wiring the actions they share (`MapActions`): launching from the tracker through the launch popover (or every ready ticket at once), opening a finished launch's pull request, sending a pull request's failing checks or review to its session, opening sessions (in their launch's worktree context, not the map's), docs (a link doc opens in the browser) and doc changes, hand edits, Needs review, Break down, writing or adding a doc. |
| `MapOverview.tsx` | A map's Overview: title, stage and description, + New ticket and Ask the map; the Recommended next card (what, why now, who acts, "Why this?"); Needs your attention (decisions, agents waiting, finished tickets, doc changes, suggestions, pull requests to fix or merge); Needs review (`MapNeedsReview.tsx`); the current milestone with only its tickets in motion; agents working and waiting; Feature context, Decisions and Since your last visit on the side, each folding to its header (kept per map in this browser) and showing three rows, then Show all. `Chip`. |
| `MapDecisions.tsx` | A map's Decisions: open ones first, then decided, and one at a time to edit, decide (with what was decided), reopen or remove, with the tickets it blocks picked by milestone; + Decision. |
| `MapDocs.tsx` | A map's Docs, as in the frame: search, role filters and a card per doc (roles, proposed changes, linked tickets, when it changed; ⋯ or right-click to edit details, open or remove), Context coverage, + Add document (new doc, existing doc, a link to a design or prototype). The reader beside it edits the accepted version in place (`Editor`, embedded) or renders it with one proposed change applied, the banner to review its proposed changes, Ask about this, Attach to ticket (whole doc, or a section from On this page, where each row also copies a link and jumps to it), notices for open decisions citing it, and Connected work and its decisions. Edit details covers a link's title and address, roles, milestones and section (new, rename, remove). |
| `MapNeedsReview.tsx` | The Overview's Needs review: suggestions approved or dismissed in place (a proposed plan's milestones and a plan change's steps picked one by one), blocked tickets, and open pull requests the attention list leaves out, each with its action. |
| `MapMilestones.tsx` | The Milestones page: a strip of milestones (done, current, next), the selected one's header and progress, its tickets as a table (work status apart from agent activity; filters All open, Needs you, Ready; done tickets hidden until asked; Select tickets to launch several), Ready to start (independent tickets, started each in its own worktree), Agents (`MapAgents.tsx`), and the definition of done (tick, edit, add, remove). Hand edits (rename, describe, reorder, move, set status, pin, remove) from ⋯ menus and right-click. |
| `MapTicket.tsx` | A ticket, in two columns. Left: the title (typed into in place), Up next, the description (`MarkdownField`), its acceptance criteria (an input each, judged by the last wrap-up; Enter adds, Backspace on an empty one removes) and its launches (worktree, branch, sessions, wrap-up cut to three lines, pull request and its health, journal). Right: Review the work, status (settable by hand), what it waits for (`MultiSelect`), the docs it relies on (link a whole doc; sections attach from Docs) and the code project. |
| `MapBrief.tsx` | The agent brief before a ticket starts (every single-ticket start, and Review N briefs walking several): the ticket's objective, acceptance criteria and constraints (Edit brief changes the ticket, plus a note for this start only), the readiness check, the docs the agent is pointed to (+ Attach context, unlink), Session setup (worktree, code project, permissions from the Claude command and the map's checks) and the full brief text, from `previewMapBrief`. Start agent starts them, several as one batch. |
| `MapReview.tsx` | Reviewing a ticket's work: the agent's state and worktree, each launch's wrap-up (View changes), the evidence for each acceptance criterion and the checks run, what it didn't verify, and the doc updates its launches proposed (a preview, the full diff, Include when marking done). Request changes sends the user's text to the session; the next step follows the work: Open pull request, Review PR (and send failing checks or the PR review back), then Mark done & update map once merged. |
| `MapActivity.tsx` | A map's Activity, as in the frame: Since your last visit (headline, reviews ready, doc changes proposed, blocking decisions, counted from the later of the last visit and **Mark all as seen**), the log by day with filters (All, Agents, Docs, Decisions, Milestones) and **Needs action**, today's entries as cards and older ones as rows, and a detail panel for the picked entry: an agent's state, worktree, what came back and its proposed doc change (**Review handoff**, **Open source session**, its batch's coordinator), a decision, doc changes (**Review in Docs**), tickets and milestones, suggestions. |
| `MapAgents.tsx` | The Milestones page's Agents card: every agent working from the map (batches first, each with its coordinator, then other work), a row opening its session; `CoordinatorControls` (open, resume, or the offer of a coordinator), also on Activity. |
| `MapAsk.tsx` | Ask the map: the map agent's conversation (streamed), permission cards, Break down. |
| `MapParts.tsx` | Pieces the map screens share: `UpNextBlock`, `StatusDot`, `ClampedText` (text cut to a few lines with More / Less), and `LaunchPopover` (the one-click launch confirmation: worktree mode, for a group one worktree for all or one each, its own worktree by default when a session is already working in the milestone's, notes such as unmet dependencies and, when ambiguous, the code project) with `launchProjects`. |
| `MapDialog.tsx` | New context map, or a map's settings: title, description, code projects (with the checks that verify work in each), the default launch mode, and the sweep. |
| `AddMapDocDialog.tsx` | Adds a doc to a map: a new one (a title that heads it and, until typed, sets its path; optionally with a brainstorm thread) or an existing one, with milestones and section; also **Add to map…** from a doc's tab, picking the map. |
| `MultiSelect.tsx` | The dropdown the map screens pick with instead of checkbox lists: picks shown as chips in the trigger, a fuzzy-filtered list (keys like `M4` or `OMN-18` before each label, optional group headings), each row toggling; `single` picks one. Fixed-positioned from its trigger so popovers and dialogs never clip it. |
| `MarkdownField.tsx` | Short markdown stored outside the docs (a ticket's description) that reads as rendered and edits in place with live preview: a click away or ⌘Enter saves, Escape puts it back. No CRDT behind it. |
| `TerminalView.tsx` | A terminal tab: `@xterm/xterm` with fit and web-links, drawn from main's snapshot plus newer output only; sends keystrokes and size; the exit bar with Resume session / Start a new session / Restart shell; for an implementation session, an "Implementing <doc>" bar that opens the doc, and for a map's session a "From the context map" bar that opens the map. |
| `Editor.tsx` | CodeMirror 6 bound to a doc's Yjs replica (`y-codemirror.next`); `doc`, `code` and `diff` modes; wires in live preview and thread markers. `embedded` puts it inside a page (the map's Docs reader): it grows with its text; editors on the same file share their typing through `lib/editorPeers.ts`. |
| `StatusBar.tsx` | Bottom bar: context label, branch, uncommitted +/− line counts, pull, Commit (opens the Changes tab), the last status message, Claude Code status. |
| `ClaudeStatus.tsx` | Claude Code installed / signed in / provider indicator. |
| `NewTabButton.tsx` | The + after the last tab: New Claude session, New shell, Claude command…. |
| `ClaudeCommandDialog.tsx` | Dialog for the extra arguments Claude sessions start with (`claude <args>`). |
| `ContextMenu.tsx` | Right-click menu, also used as the + menu. |
| `OpenLinkDialog.tsx` | Asks before opening a terminal hyperlink (OSC 8): shows where it goes, then Open, Copy link or Cancel. Refuses what main won't open. |
| `InlineInput.tsx` | Inline text input for new doc, file, folder and worktree names. |
| `ResizeHandle.tsx` | Drag handle for pane widths; double-click resets. |

**Tests:** none here; the UI is tested end to end through CDP ([docs/threads.md](../../../../docs/threads.md) → Developing).
