# P12 part 3: the PR tab. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A **PR** tab in the right panel for code worktrees. It shows the branch's pull request (state, base, checks, conversation and review comments), sends ticked comments to a Claude agent behind the user's prompt template, and creates a draft PR when there is none.

**Architecture:**
- **GitHub:** every `gh` call goes through one injectable `GhRunner` in `core/repo/github.ts`. `ghPullRequestDetail` finds the branch's PR, then reads it with `gh pr view <n> --json …` and its review threads with `gh api graphql`. Everything is parsed with guards into a `PullRequestDetail`, and cached 60 s per worktree and branch.
- **Orchestration:** `core/review/pullRequests.ts` decides whether the tab can work at all (`gh` installed, a GitHub remote, on a branch), sends comments, and creates the draft PR (push with `-u` when needed, then `gh pr create --draft`).
- **Sending:** reuses G-D's delivery. `sendReview`'s "paste into a terminal or start a session, then mark sent" part is split out as `deliverPrompt`. PR comments get their own message format with the template in front. The template is kept in `<userData>/review-settings.json`.
- **The UI:**
  - A `PullRequestPanel` component with three parts: header, checks and comments.
  - A hook that refreshes on open, on focus, and every 30 s while a check runs.
  - The send flow reuses `AgentPicker`, which gains an **Edit prompt…** footer.
  - Two dialogs: the prompt template and Create draft PR.

**Tech Stack:** Electron, React, TypeScript, the user's own `gh` (2.97 on the user's machine), vitest with real temp repos and recorded `gh` JSON fixtures.

**Spec:** [docs/superpowers/specs/2026-10-26-orca-polish-design.md](../specs/2026-10-26-orca-polish-design.md), section G-E. It builds on G-D (part 2): `sendReview`, `AgentPicker`, `ReviewCommentStore`, `fenced`, and `TerminalManager.sendPrompt`. G-F (part 4) reads `PullRequestDetail` from this plan, so keep its field names.

**Verified against the installed `gh` 2.97:**
- `gh pr view --json` accepts `id, number, title, state, isDraft, url, baseRefName, baseRefOid, headRefName, headRefOid, author, comments, reviews, statusCheckRollup`.
- In `gh api`, the `-F` field values `{owner}` and `{repo}` are filled in from the current folder's repository. `--input -` reads the request body from stdin.

## Global Constraints

- [docs/patterns.md](../../patterns.md):
  - No `as` casts, including `as const` and casts in tests.
  - Guards for outside data: `gh` output, JSON files and IPC arguments.
  - Per-file stores serialise their own I/O.
  - Atomic writes: write `.tmp`, then `rename`.
  - `OpResult` for refusals the user should see.
  - `/** */` comments only for a why that isn't obvious.
- [src/README.md](../../../src/README.md) boundaries: the renderer reaches main only through `window.manta`, `shared/` imports nothing, and `core/` never imports Electron.
- New, renamed or removed files update their folder's README table in the same task. `directoryReadmes.test.ts` enforces this.
- A task is done only when `npm run typecheck` and `npm test` pass.
- **Tests never reach GitHub.** Every `gh` call goes through the injected `GhRunner`. Pushes go to a bare temp `origin`.
- **UI checks run on an isolated build** with `MANTA_USER_DATA=<scratch>/profile MANTA_FAKE_AGENT=1`, as in part 2:
  - Point `MANTA_FAKE_GH=<path>` at a stand-in `gh` script that prints the fixtures (Task 4 adds the switch).
  - Never use the user's real `gh` login in a UI run without asking first.
- No live Claude Code runs.
- **Git:** work on branch `p12-part3`, cut from wherever part 2 lands (`main` once it's merged, otherwise `p12-part2`). Stage each task's files and don't commit until the user asks.
- **UI:** minimal and clean, in Manta's style.
  - Few borders, muted secondary text, icons over labelled buttons where the meaning is clear.
  - Reuse `.row`, `.icon-button`, `.primary-button`, `.popover`, `.badge`, `.change-section`, `.dialog`, and the `--bg-*`, `--text-*`, `--accent`, `--green`, `--red` and `--yellow` variables.
- Sending never switches tabs or contexts.
- **Nothing is written to GitHub except Create draft PR.** It runs only after the user presses its button in the dialog.
- **The default template text, verbatim:** "Analyse these PR comments, assign a reference to each like C1, C2, C3… Create a table with what can be addressed with your recommendations, split actionable items from items which require more thought."

## Review Focus

1. **Missing or unexpected `gh` output.** This covers no `gh`, a `gh` that isn't logged in, no GitHub remote, a detached HEAD, a `statusCheckRollup` entry with an unknown state, a thread whose comment has no author (a deleted user), and invalid JSON.
   - The tab says why in one line, or it skips the bad entry. It never crashes or shows a blank tab.
   - "`gh` failed" must never read as "no PR", or the user would be offered **Create draft PR** on a branch that already has one.
   - Pinned in Tasks 1 and 2.
2. **A `gh` command that hangs** (a network stall, or an auth prompt waiting on a TTY):
   - Every call has a timeout and runs with `GH_PROMPT_DISABLED=1`.
   - The tab shows the error, and refreshes don't pile up behind it.
   - Pinned in Task 1 (the runner) and Task 5 (one refresh in flight).
3. **Comment text containing backticks or paste markers:** a hunk with ```` ``` ```` in it, or a body with `\x1b[201~` in it. It still reaches the agent as one prompt, with the fences intact. Pinned in Task 2 (format) and by G-D's `sendPrompt` marker stripping.
4. **Create draft PR on a branch with no upstream, or with unpushed commits:** it pushes first, and `gh` doesn't prompt. A refused push (non-fast-forward, no permission) shows git's own message, and no PR is created. Pinned in Task 3.
5. **A newly created PR shows straight away,** not after the 60 s cache runs out. Creating a PR or forcing a refresh bypasses the cache. Pinned in Tasks 1 and 3.

```ts
export interface PullRequestCheck { name: string; state: 'passed' | 'failed' | 'running' | 'skipped'; url: string | null }
export interface PullRequestReply { author: string; body: string; createdAt: string }
export interface PullRequestComment {
  /** GitHub's node id: a review thread's, a conversation comment's or a review's. */
  id: string
  kind: 'thread' | 'comment' | 'review'
  author: string
  body: string
  url: string
  createdAt: string
  /** Threads only; null otherwise. `line` is null for an outdated thread with no current line. */
  path: string | null
  line: number | null
  side: 'old' | 'new' | null
  hunk: string | null
  resolved: boolean
  outdated: boolean
  /** A thread's later comments, oldest first. */
  replies: PullRequestReply[]
  /** A review's verdict; null for the other kinds. */
  verdict: 'approved' | 'changes requested' | 'commented' | null
}
export interface PullRequestDetail {
  /** Node id, for GraphQL mutations (G-F). */
  id: string
  number: number
  title: string
  state: 'open' | 'draft' | 'merged' | 'closed'
  url: string
  baseRefName: string
  baseRefOid: string
  headRefName: string
  headRefOid: string
  author: string
  /** The `gh` user; G-F compares it with `author`. */
  viewer: string
  checks: PullRequestCheck[]
  comments: PullRequestComment[]
  /** More review threads than one page (100); the rest aren't listed. */
  truncated: boolean
}
export type PullRequestStatus =
  | { kind: 'unavailable'; reason: string }
  | { kind: 'none'; branch: string }
  | { kind: 'found'; pr: PullRequestDetail }
```

- **Produces, in `github.ts`:**
  - `type GhResult = { ok: true; stdout: string } | { ok: false; message: string }`
  - `type GhRunner = (cwd: string, args: readonly string[], input?: string) => Promise<GhResult>`
  - `ghRunner(options: GhOptions): GhRunner`
    - It uses `execFile` with `TIMEOUT_MS` and `env` plus `GH_PROMPT_DISABLED=1`, and writes `input` to stdin when given.
    - If `gh()` is null, it returns `{ ok: false, message: "gh isn't installed" }`.
    - When `gh` fails, `message` is its stderr, trimmed. If stderr is empty, it's the error's message.
  - `ghPullRequestDetail(run: GhRunner): (root: string, branch: string, options?: { force?: boolean }) => Promise<{ found: PullRequestDetail | null } | { failed: string }>`. It runs:
    1. `pr list --head <branch> --state all --json number --limit 1`
    2. If a PR was found: `pr view <n> --json id,number,title,state,isDraft,url,baseRefName,baseRefOid,headRefName,headRefOid,author,comments,reviews,statusCheckRollup`
    3. Then `api graphql -F owner={owner} -F name={repo} -F number=<n> -f query=<THREADS_QUERY>`
    - Answers are cached 60 s per `root\0branch`. `force` skips the cache and replaces the entry. Failures aren't cached.
  - `THREADS_QUERY` reads:
    - `viewer { login }`
    - `repository.pullRequest.reviewThreads(first: 100) { pageInfo { hasNextPage } nodes { id isResolved isOutdated path line originalLine diffSide comments(first: 50) { nodes { author { login } body url createdAt diffHunk } } } }`
  - `parsePullRequestDetail(view: string, threads: string): PullRequestDetail | undefined` is exported for tests.
  - `ghPullRequests` keeps its signature and tests, and now runs through `ghRunner`.
- **Parsing rules** (an unrecognised entry is skipped with `console.error`; an unrecognised top level is `undefined`):
  - **State:** `OPEN` with `isDraft` is `draft`. Otherwise `OPEN`, `MERGED` and `CLOSED` map to `open`, `merged` and `closed`.
  - **`CheckRun` entries** (`__typename: "CheckRun"`; the name is `name`, the URL `detailsUrl`):
    - When `status` is anything other than `COMPLETED`, the state is `running`.
    - Otherwise the state comes from `conclusion`:
      - `SUCCESS` or `NEUTRAL`: `passed`
      - `SKIPPED`: `skipped`
      - `FAILURE`, `TIMED_OUT`, `CANCELLED`, `ACTION_REQUIRED`, `STARTUP_FAILURE` or `STALE`: `failed`
  - **`StatusContext` entries** (the name is `context`, the URL `targetUrl`):
    - `SUCCESS`: `passed`
    - `FAILURE` or `ERROR`: `failed`
    - `PENDING` or `EXPECTED`: `running`
  - **Check URLs:** an empty URL is `null`.
  - **Threads:**
    - A thread becomes one `PullRequestComment` of kind `thread`. Its first comment gives `author`, `body`, `url`, `createdAt` and `hunk`, and the rest become `replies`.
    - `line` is `line ?? originalLine`. `side` is `LEFT` → `old`, `RIGHT` → `new`.
    - A thread with no comments is skipped.
  - **Conversation and reviews:**
    - Each conversation comment becomes kind `comment`.
    - A review with an empty body is skipped. Any other review becomes kind `review`, with `verdict` from its state: `APPROVED`, `CHANGES_REQUESTED` and `COMMENTED` map to `approved`, `changes requested` and `commented`.
    - Ids come from the entries' `id` fields.
  - **Authors:** a null `author` (a deleted account) reads as `ghost`, GitHub's own name for it.
- **Fixtures:**
  - Hand-written in the shape `gh` 2.97 prints. Take the field names from `gh pr view --help` and GitHub's GraphQL schema; don't guess them.
  - `pr-view.json` has one passing, one failing and one running check, one `StatusContext`, two conversation comments, one review with a body and one without, and an unknown-state check.
  - `pr-threads.json` has one resolved and one unresolved thread, one outdated thread with `line: null`, a thread with a reply, one null author, and `hasNextPage: false`.

**Files:**

**Interfaces:**
- **Consumes:** `GhRunner` and `ghPullRequestDetail` (Task 1), `Git.branchBase` and `Git.upstream`.
- **Produces, in `Git`:**
  - `remoteUrls(): Promise<string[]>`: fetch URLs from `git remote -v`, de-duplicated.
  - `pushBranch(branch: string, setUpstream: boolean): Promise<void>`: `git push [-u] origin <branch>`. It throws `GitError`, carrying stderr.
  - `aheadOfUpstream(): Promise<number>`: `rev-list --count @{u}..HEAD`, or 0 when there's no upstream.
  - `lastCommitSubject(): Promise<string>`: `log -1 --format=%s`, or `''` when there are no commits.
- **Produces, in `pullRequests.ts`:**
  - `hasGitHubRemote(urls: readonly string[]): boolean`: true for `github.com` in https or ssh form (`git@github.com:o/r.git`, `ssh://git@github.com/o/r`, `https://github.com/o/r`).
  - `prBaseName(ref: string): string`: strips a leading `origin/`, so `origin/main` becomes `main` and `main` stays `main`.
  - `class PullRequests`:
    - `constructor(options: { run: GhRunner; ghInstalled: () => boolean })`. It owns one `ghPullRequestDetail(run)`.
    - `status(root: string, git: Git, options?: { force?: boolean }): Promise<PullRequestStatus>`. It checks, in this order:
      1. If `gh` isn't installed: `unavailable`, "Install GitHub's gh and run gh auth login to see pull requests".
      2. If there's no GitHub remote: `unavailable`, "This repo has no GitHub remote".
      3. If HEAD is detached: `unavailable`, "Not on a branch".
      4. If `gh` failed: `unavailable` with `gh`'s message.
      5. Otherwise `none` or `found`.
    - `draftDefaults(git: Git, chosenBase: string | null): Promise<{ title: string; base: string }>`
      - `title` is `lastCommitSubject()`.
      - `base` is `prBaseName(chosenBase ?? branchBase(null)?.label ?? 'main')`.
    - `createDraft(root: string, git: Git, input: { title: string; body: string; base: string }): Promise<OpResult>`
      - **Refusals:**
        - an empty title: "Give the PR a title"
        - a detached HEAD: "Not on a branch"
        - `base` equal to the branch: "Pick a base other than this branch"
      - **The steps:**
        1. With no upstream, `pushBranch(branch, true)`. If it's ahead of its upstream, `pushBranch(branch, false)`.
        2. Then `gh pr create --draft --title <t> --body <b> --base <base> --head <branch>`.
        3. On success: `{ ok: true, message: 'Draft PR created: <url from stdout, trimmed>' }`, and the next `status` for that root and branch is forced.
      - A push or `gh` failure returns `{ ok: false, message }` with git's or `gh`'s own text. No `gh` call runs after a failed push.
    - `cached(root: string): PullRequestDetail | null`: the last `found` detail for the root's current branch. G-F reads it too.
    - `sendComments(request: { store: ReviewCommentStore; terminals; root: string; ids: readonly string[]; template: string; target: ReviewTarget; size }): Promise<OpResult>`: calls `sendPullRequestComments` (Task 2) with `cached(root)`. If no PR is cached, it refuses "Refresh the PR tab and try again".

- **Calls this plan makes that the spec doesn't** (each is a ruling for the executor to ledger if it changes):
  - **The finding call:** `ghPullRequestDetail` makes its own `pr list` call instead of going through `ghPullRequests`' cache. `ghPullRequests` still serves implementation chips, unchanged. Reusing its cache would hide a new PR for up to a minute after Create draft PR, and it can't say why `gh` failed.
  - **Unpushed commits:** Create draft PR also pushes when the branch has an upstream but unpushed commits. Otherwise the draft would be missing them.
  - **Sent marks:** PR comments get the same "sent to X" marks as G-D's, in the same per-worktree file. That's consistent, and G-F extends the same file.
  - **Default ticks:** unresolved, current threads start ticked. That makes "two clicks" from the spec's success line true.
  - **No live recording:** the fixtures are hand-written to `gh`'s documented shape instead of recorded live, because recording would need the user's GitHub login. If the user wants, they can record one with `gh pr view <n> --json … > pr-view.json` on a real PR, and the executor swaps it in.
  - **The forced timer:** the 30 s running-check timer forces past the cache. Otherwise the 60 s cache would make it a 60 s timer.
